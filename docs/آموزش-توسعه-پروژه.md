# راهنمای کامل Kotlin + Android برای توسعه‌دهنده Java

> **مخاطب:** کسی که **Java** بلد است، ولی **اصلاً Kotlin** و **Android** را نمی‌شناسد و می‌خواهد همین پروژه (`PersonalTimeTracker`) را توسعه بدهد.
>
> **هدف نهایی:** خواندن کد پروژه، فهم معماری، و اضافه کردن فیچر بدون ترس از سینتکس Kotlin.

---

## 1. اپ چیست؟

**PersonalTimeTracker** اپ اندروید آفلاین برای:

- ثبت **ورود / خروج** (تردد)
- محاسبه **مرخصی و اضافه‌کار** با قوانین شناوری
- مدیریت **تسک** با تایمر و لاگ روزانه
- **گزارش** روزانه / هفتگی / ماهانه
- تقویم **جلالی**، ویجت، نوتیفیکیشن، لوکیشن محل کار، بکاپ

| موضوع | انتخاب این پروژه |
|---|---|
| زبان | **Kotlin** (نه Java) |
| UI | View کلاسیک (نه Compose) |
| دیتابیس | Room روی SQLite |
| معماری | یک Activity + چند Fragment + یک Repository |

## 2. مفاهیم پایه Android

اگر از Java بک‌اند یا دسکتاپ آمده‌ای:

| مفهوم Android | شبیه در Java؟ | توضیح |
|---|---|---|
| `Application` (`App.kt`) | Context سراسری / Singleton | یک‌بار هنگام شروع اپ |
| `Activity` (`MainActivity`) | پنجره اصلی | میزبان UI |
| `Fragment` | پنل داخل پنجره | هر تب یک Fragment است |
| `AndroidManifest.xml` | تنظیمات استقرار | ثبت صفحه، پرمیشن، Receiver |
| `res/` | منابع ثابت | layout، رنگ، آیکون |
| Room Entity/DAO | JPA Entity / Repository | جدول و کوئری |
| Coroutine | Executor مدرن | کار غیرمسدودکننده |
| `Flow` | Observer / Stream | داده زنده از دیتابیس |
| Intent | پیام بین کامپوننت‌ها | باز کردن صفحه، کلیک ویجت |

### چرخه حیات Fragment

```
onCreate → onCreateView → onViewCreated → onStart → onResume
                              ↓
                         (کاربر می‌رود)
                              ↓
onPause → onStop → onDestroyView → (گاهی) onDestroy
```

**قانون عملی:** UI را در `onCreateView` بساز؛ داده را با `viewLifecycleOwner.lifecycleScope` بگیر.

### دسترسی به Repository

```kotlin
val repo = (requireActivity().application as App).repository
```

معادل Java:

```java
App app = (App) getActivity().getApplication();
AppRepository repo = app.getRepository();
```

## 3. Kotlin از صفر برای برنامه‌نویس Java

این بخش طوری نوشته شده که **حتی اگر یک خط Kotlin هم ندیده‌ای**، قدم‌به‌قدم جلو بروی.
هر زیربخش: مفهوم → مقایسه با Java → مثال ساده → مثال از همین پروژه.

---

### 3.0 Kotlin چیست و فایل‌ها چطورند؟

- Kotlin روی همان JVM اجرا می‌شود؛ با Java ۱۰۰٪ سازگار است.
- پسوند فایل: `.kt` (به‌جای `.java`)
- پکیج مثل Java است: `package com.personal.timetracker`
- **یک فایل می‌تواند چند کلاس داشته باشد** (برخلاف قانون سخت Java که یک public class per file).
- در این پروژه همه چیز Kotlin است؛ Java نمی‌نویسیم.

Import مثل Java است:

```kotlin
import android.app.Application
import com.personal.timetracker.data.repository.AppRepository
```

### 3.1 متغیرها: `val` و `var`

| Kotlin | معادل ذهنی Java |
|---|---|
| `val x = 10` | `final int x = 10;` — بعداً عوض نمی‌شود |
| `var y = 10` | `int y = 10;` — قابل تغییر |

```kotlin
val name = "Ali"      // نوع را خودش می‌فهمد: String
var age = 30          // Int
age = 31              // OK
// name = "Reza"     // خطا! val را نمی‌شود عوض کرد
```

**قانون طلایی در این پروژه:** تا جایی که می‌توانی `val` استفاده کن. بیشتر Entityها و نتایج کوئری `val` هستند.

تایپ را می‌توانی صریح بنویسی:

```kotlin
val duration: Int = 0
val exitTime: String? = null
```

### 3.4 توابع (Functions)

**Java**

```java
public int add(int a, int b) {
    return a + b;
}
```

**Kotlin**

```kotlin
fun add(a: Int, b: Int): Int {
    return a + b
}

// فرم کوتاه وقتی فقط یک عبارت است:
fun add2(a: Int, b: Int): Int = a + b
```

نکات مهم:

1. کلمه `fun` به‌جای نوع برگشتی اول می‌آید.
2. نوع پارامتر **بعد** از اسم می‌آید: `a: Int` نه `int a`.
3. اگر چیزی برنگرداند، `: Unit` اختیاری است (مثل void).

#### آرگومان پیش‌فرض و نام‌دار (خیلی مهم در این پروژه)

```kotlin
fun checkIn(
    date: String = TimeUtils.today(),
    entryTime: String = TimeUtils.nowTime()
) { ... }
```

فراخوانی:

```kotlin
checkIn()
checkIn(entryTime = "09:30")
checkIn(date = "2026-08-26", entryTime = "08:00")
```

در Java برای همین کار چند overload می‌نوشتی.

#### تابع داخل تابع / local function

گاهی داخل یک متد، تابع کمکی محلی تعریف می‌شود. فعلاً لازم نیست عمیق شوی؛ اگر دیدی نترس.

### 3.5 شرط‌ها: `if` و `when`

#### `if` یک عبارت است (مقدار برمی‌گرداند)

```kotlin
val label = if (duration > 0) "کار کرده" else "صفر"
```

معادل Java با متغیر موقت یا ternary.

#### `when` جایگزین `switch` قوی‌تر

```kotlin
val title = when (status) {
    "active" -> "در حال کار"
    "completed" -> "تمام شده"
    else -> "نامشخص"
}
```

بدون موضوع (مثل if-else زنجیره‌ای) — در پروژه برای تسک:

```kotlin
val status = when {
    remaining <= 0 -> "done"
    task.status == "new" -> "in_progress"
    else -> task.status
}
```

`when` باید همه‌حالت را پوشش دهد یا `else` داشته باشد وقتی به‌عنوان عبارت استفاده می‌شود.

### 3.7 کالکشن‌ها (List, Map, Set)

| Kotlin | Java تقریبی |
|---|---|
| `listOf(1, 2, 3)` | `List.of` غیرقابل تغییر |
| `mutableListOf(1, 2)` | `ArrayList` |
| `mapOf("a" to 1)` | `Map.of` |
| `mutableMapOf()` | `HashMap` |
| `setOf(...)` | `Set` |

```kotlin
val nums = listOf(1, 2, 3, 4)
val evens = nums.filter { it % 2 == 0 }     // [2, 4]
val doubled = nums.map { it * 2 }           // [2, 4, 6, 8]
val sum = nums.sum()
val first = nums.firstOrNull()
val lastCompleted = dayRecords
    .filter { it.id != active.id && it.exitTime != null }
    .lastOrNull()
```

`it` یعنی «همان آیتم جاری در Lambda» — خیلی می‌بینی.

عملیات رایج که در پروژه می‌آید:

| متد | معنی |
|---|---|
| `filter { }` | فیلتر |
| `map { }` | تبدیل هر آیتم |
| `firstOrNull()` | اولی یا null |
| `lastOrNull()` | آخری یا null |
| `any { }` | آیا حداقل یکی؟ |
| `sumOf { }` | جمع روی فیلد |
| `sortedBy { }` | مرتب‌سازی |
| `groupBy { }` | گروه‌بندی |
| `takeIf { }` / `takeUnless { }` | نگه داشتن مقدار اگر شرط برقرار باشد |

### 3.8 Null Safety — مهم‌ترین تفاوت با Java

در Java تقریباً هر reference می‌تواند `null` باشد → `NullPointerException`.

در Kotlin نوع‌ها دو دسته‌اند:

```kotlin
var a: String = "hi"
// a = null   // خطای کامپایل!

var b: String? = "hi"
b = null      // OK
```

علامت `?` یعنی «ممکن است null باشد».

#### عملگرهای حیاتی

```kotlin
val exit: String? = record.exitTime

// Safe call: اگر null بود، کل عبارت null می‌شود
val len: Int? = exit?.length

// Elvis: اگر چپ null بود، راست را بگیر
val text: String = exit ?: "هنوز خارج نشده"

// ترکیب
val len2: Int = exit?.length ?: 0

// Not-null assertion — خطرناک (مثل اجبار در Java)
val forced: String = exit!!   // اگر null باشد → کرش
```

#### Early return با null

الگوی خیلی رایج در Repository:

```kotlin
suspend fun checkOut(exitTime: String = TimeUtils.nowTime()) {
    val active = attendanceDao.getActive() ?: return
    // از اینجا به بعد active قطعاً null نیست (smart cast)
}
```

معادل ذهنی Java:

```java
AttendanceEntity active = attendanceDao.getActive();
if (active == null) return;
```

#### Smart cast

بعد از چک null، کامپایلر خودش نوع را باریک می‌کند:

```kotlin
val s: String? = ...
if (s != null) {
    println(s.length)  // اینجا s مثل String غیرnull است
}
```

#### `lateinit` و `by lazy`

وقتی می‌دانی متغیر بعداً (مثلاً در `onCreate`) مقدار می‌گیرد ولی نمی‌خواهی nullable باشد:

```kotlin
private lateinit var binding: ActivityMainBinding
private lateinit var repository: AppRepository
```

- قبل از مقداردهی استفاده کنی → کرش.
- در پروژه برای Binding و Repository زیاد است.

`lazy`: اولین بار که خوانده شد ساخته می‌شود:

```kotlin
val db by lazy { AppDatabase.get(context) }
```

### 3.13 Lambda و توابع مرتبه بالاتر

Lambda یعنی «تکه کدی که مثل مقدار جابه‌جا می‌شود».

**Java قدیمی**

```java
button.setOnClickListener(new View.OnClickListener() {
    @Override public void onClick(View v) {
        doCheckIn();
    }
});
```

**Kotlin**

```kotlin
button.setOnClickListener { doCheckIn() }

// اگر پارامتر لازم باشد:
button.setOnClickListener { view -> doCheckIn() }

// اگر فقط یکی باشد، اسم پیش‌فرض it است:
list.filter { it.status == "active" }
```

آخرین Lambda را می‌توانی بیرون پرانتز نوشت (convention):

```kotlin
lifecycleScope.launch {
    // بدنه‌ی lambda
}
```

معادل ذهنی: `launch(new Runnable() { ... })` ولی تمیزتر.

نوع تابع در Kotlin:

```kotlin
val onDone: (String) -> Unit = { msg -> println(msg) }
```

یعنی تابعی که `String` می‌گیرد و چیزی برنمی‌گرداند.

### 3.14 Scope functions: `apply` / `also` / `let` / `run` / `with`

در UI این پروژه **خیلی زیاد** هستند. بدون فهمیدن‌شان Fragmentها گیج‌کننده‌اند.

| تابع | گیرنده داخل بلاک | خروجی | کاربرد رایج |
|---|---|---|---|
| `apply` | `this` | خود آبجکت | پیکربندی هنگام ساخت |
| `also` | `it` | خود آبجکت | ساید‌افکت (لاگ) |
| `let` | `it` | آخرین خط | کار روی nullable |
| `run` | `this` | آخرین خط | محاسبه روی آبجکت |
| `with` | `this` | آخرین خط | شبیه run ولی تابع جدا |

#### مثال واقعی سبک پروژه

```kotlin
val btn = MaterialButton(context).apply {
    text = "ورود"
    setOnClickListener {
        // ...
    }
}
parent.addView(btn)
```

معنی خط‌به‌خط:

1. یک `MaterialButton` بساز
2. داخل `apply` روی همان دکمه (`this`) تنظیمات را بزن
3. همان دکمه را برگردان داخل `btn`

#### `let` برای null

```kotlin
exitTime?.let { t ->
    println("خروج در $t")
}
```

فقط اگر `exitTime` null نباشد اجرا می‌شود.

#### `also` در Repository

### 3.19 Coroutine از صفر (حتماً بخوان)

#### چرا؟

در Android، **Main Thread** مسئول UI است. اگر روی آن دیتابیس/شبکه سنگین انجام بدهی، اپ قفل می‌شود (ANR) یا کرش می‌کند.

در Java قدیمی: `AsyncTask` / `Executor` / `Thread`.  
در Kotlin مدرن این پروژه: **Coroutines**.

#### سه کلمه کلیدی

| کلمه | معنی ساده |
|---|---|
| `suspend fun` | این تابع می‌تواند «صبر کند» بدون قفل کردن Thread |
| `launch { }` | یک کار پس‌زمینه/هم‌زمان شروع کن (مثل fire-and-forget با ساختار) |
| `withContext(Dispatchers.IO) { }` | این تکه را روی Threadهای IO اجرا کن، بعد برگرد |

#### مثال خط‌به‌خط از MainActivity

```kotlin
lifecycleScope.launch {
    val settings = withContext(Dispatchers.IO) {
        (application as App).repository.getSettings()
    }
    applyChrome(settings.themeColor, settings.isDarkMode)
}
```

ترجمه به زبان آدمیزاد:

1. یک Coroutine وابسته به عمر Activity شروع کن.
2. برو روی IO، تنظیمات را از دیتابیس بخوان.
3. وقتی آماده شد، برگرد Main و UI را رنگ کن.

#### `Dispatchers`

| Dispatcher | برای چه؟ |
|---|---|
| `Main` | UI |
| `IO` | دیتابیس، فایل، شبکه |
| `Default` | محاسبات CPU |

#### قانون عملی پروژه

- متدهای DAO که یک‌باره کار می‌کنند → `suspend`
- از Fragment/Activity آن‌ها را فقط داخل `lifecycleScope.launch` یا `viewLifecycleOwner.lifecycleScope.launch` صدا بزن
- اگر صریحاً IO می‌خواهی: `withContext(Dispatchers.IO)`

#### چک‌این واقعی

```kotlin
viewLifecycleOwner.lifecycleScope.launch {
    repo.checkIn()
}
```

چون `checkIn` خودش `suspend` است و داخلش DAO را صدا می‌زند.

### 3.24 خواندن یک متد واقعی: `checkIn`

```kotlin
suspend fun checkIn(
    date: String = TimeUtils.today(),
    entryTime: String = TimeUtils.nowTime()
) {
    val active = attendanceDao.getActive()
    if (active != null && active.date == date) return

    attendanceDao.insert(
        AttendanceEntity(date = date, entryTime = entryTime, status = "active")
    )

    val settings = getSettings()
    if (settings.notifEnabled && date == TimeUtils.today()) {
        val required = requiredMinutesFor(date, settings)
        val end = TimeCalc.applyFlex(
            entryTime, settings.startWorkTime, settings.flexibleMinutes, required
        ).suggestedEnd
        NotifHelper.scheduleWorkEnd(
            appContext, end, settings.notifMinutesBefore,
            settings.notifTitle, settings.notifBody
        )
    }
    try { DynamicAppIcon.syncNow(appContext) } catch (_: Exception) {}
}
```

چک‌لیست مفاهیم داخل همین یک متد:

- [ ] `suspend`
- [ ] پارامتر پیش‌فرض
- [ ] null check
- [ ] ساخت `data class` با named args
- [ ] فراخوانی `object` (`TimeCalc`, `NotifHelper`)
- [ ] دسترسی به پراپرتی `settings.notifEnabled`
- [ ] try/catch با `_`

اگر همه را فهمیدی، برای ادامه پروژه آماده‌ای.

### 3.25 جدول جامع Java ↔ Kotlin

| Java | Kotlin |
|---|---|
| `int x = 1;` | `val x = 1` یا `var x = 1` |
| `final int x` | `val x` |
| `String s = null;` | `var s: String? = null` |
| `s.length()` اگر null → NPE | `s?.length` |
| `s != null ? s : ""` | `s ?: ""` |
| `new Person()` | `Person()` |
| `person.getName()` | `person.name` |
| `void f()` | `fun f() { }` یا `fun f(): Unit` |
| `int f(int a)` | `fun f(a: Int): Int` |
| overloadها | آرگومان پیش‌فرض + named |
| `switch` | `when` |
| `static` method | `object` / `companion object` |
| Singleton | `object` |
| POJO + lombok | `data class` |
| Builder copy | `copy(...)` |
| Anonymous class | Lambda `{ }` |
| `List<T>` immutable | `List<T>` / `listOf` |
| `ArrayList` | `MutableList` / `mutableListOf` |
| Stream `.filter().map()` | `.filter { }.map { }` |
| `Optional` | `?.` و `?:` و `OrNull` |
| `implements` / `extends` | `:` |
| `@Override` | `override` |
| `instanceof` | `is` |
| `(Type) x` | `x as Type` / `x as? Type` |
| `Executor` / AsyncTask | Coroutine |
| Rx `Observable` | `Flow` |
| checked exceptions | اجباری نیست |

---

### 3.26 اشتباهات مبتدی Kotlin (قبل از Android)

1. نوشتن `Int?` همه‌جا بدون دلیل → کد زشت می‌شود؛ فقط جایی که واقعاً null معنی دارد.
2. استفاده از `!!` برای «ساکت کردن کامپایلر» → بعدها کرش.
3. گیج شدن بین `val` لیست و محتوای لیست: `val list = mutableListOf(1)` — خود reference ثابت است ولی محتوا عوض می‌شود.
4. فراموش کردن که `data class` با `=` کپی reference می‌دهد نه deep copy تو در تو (اینجا Entityها تخت‌اند، معمولاً OK).
5. فکر کردن `object` مثل instance عادی است که `new` می‌شود — نه؛ همان یک دانه است.
6. ترس از `apply` — فقط syntactic sugar برای پیکربندی است.

## پیوست C — تمرین‌های Kotlin (حتماً حل کن)

### تمرین ۱
معادل Kotlin را بنویس:

```java
public final class Utils {
    private Utils() {}
    public static int minutes(String a, String b) { return 0; }
}
```

### تمرین ۲
این Java را به Kotlin idiomatic تبدیل کن:

```java
String exit = record.getExitTime();
String text;
if (exit == null) text = "-";
else text = exit;
```

### تمرین ۳
با `data class` یک `Task` با فیلدهای `title: String`, `remaining: Int = 0` بساز و با `copy` مقدار remaining را کم کن.

### تمرین ۴
توضیح بده این خط چه می‌کند:

```kotlin
val active = attendanceDao.getActive() ?: return
```

### تمرین ۵
تفاوت `listOf` و `mutableListOf` چیست؟

### تمرین ۶
این را بخوان و بگو UI چه موقع آپدیت می‌شود:

```kotlin
repo.observeToday().collectLatest { list -> render(list) }
```

### تمرین ۷
چرا این خطرناک است؟

```kotlin
val t: String = exitTime!!
```

### تمرین ۸
معادل `apply` را بدون `apply` بنویس (همان کار، طولانی‌تر).

## پیوست D — پاسخ تمرین‌ها

**۱**

```kotlin
object Utils {
    fun minutes(a: String, b: String): Int = 0
}
```

**۲**

```kotlin
val text = record.exitTime ?: "-"
```

**۳**

```kotlin
data class Task(val title: String, val remaining: Int = 0)
val t1 = Task("گزارش")
val t2 = t1.copy(remaining = t1.remaining - 30)
```

**۴**  
اگر سشن فعالی نباشد، از تابع خارج شو؛ وگرنه `active` از این به بعد non-null است.

**۵**  
`listOf` لیست فقط‌خواندنی می‌سازد؛ `mutableListOf` قابل add/remove است. خود متغیر اگر `val` باشد reference عوض نمی‌شود.

**۶**  
هر بار داده امروز در دیتابیس عوض شود (مثلاً بعد از checkIn)، `render` دوباره صدا زده می‌شود.

**۷**  
اگر `exitTime` واقعاً null باشد اپ کرش می‌کند. بهتر: `?:` یا `?.let`.

**۸**

```kotlin
val btn = MaterialButton(context)
btn.text = "ورود"
btn.setOnClickListener { }
```

به‌جای:

```kotlin
val btn = MaterialButton(context).apply {
    text = "ورود"
    setOnClickListener { }
}
```

## پیوست E — واژه‌نامه
